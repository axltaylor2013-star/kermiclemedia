How to Run DeepSeek V3 Locally with Ollama: Complete Setup Guide for 2026

May 19, 2026 · 6 min read

If you've been watching the open-weight AI space, DeepSeek V3 is the model everyone's running on their own hardware right now. It punches well above its weight for code generation, reasoning, and long-context tasks, and the team made it permissive enough that you can actually deploy it locally without dancing around a restrictive license. The catch is that "running DeepSeek V3 locally" can mean five different things depending on your hardware, your patience, and how much quality you're willing to trade for speed.

This guide walks through a setup that actually works on consumer hardware, what to expect on each tier of machine, and the tweaks that make the difference between a model that's painful to use and one that feels like a daily driver. We'll use Ollama because it's the lowest-friction path, but the same principles apply to llama.cpp directly if you want more control.

What You Actually Need Before You Start

DeepSeek V3 is a large model. The full-precision version is over 600 billion parameters, which means nobody is running it on a laptop. What you'll actually run is a quantized version — a compressed copy that trades a small amount of accuracy for a massive reduction in memory footprint. The distilled variants (the 7B, 14B, and 32B sizes built on top of Qwen and Llama) are what most people mean when they say they're "running DeepSeek locally," and those are the ones we'll focus on here.

Hardware Reality Check

Here's roughly what each size needs:

  • 7B distilled (Q4 quantization): 6 GB of VRAM or unified memory. Works on a base M1 MacBook, an RTX 3060, or anything with at least 8 GB of system RAM if you're willing to wait.
  • 14B distilled (Q4): 10 GB of VRAM. Comfortable on an M2 Pro, RTX 4070, or any 16 GB Apple Silicon machine.
  • 32B distilled (Q4): 22 GB. You'll want an M3 Max, M4 Pro, RTX 4090, or a 36 GB+ Mac.
  • 70B distilled (Q4): 45 GB. This is M3 Max 64 GB territory, or dual GPUs.

If you've got 32 GB of unified memory or more on an Apple Silicon Mac, the 32B model is the sweet spot. It's smart enough to handle real coding tasks, fast enough to be conversational, and small enough that you're not waiting two seconds between tokens.

Installing Ollama (The Easy Part)

Ollama is a single binary that handles model downloads, GPU acceleration, and a local API server. On macOS, grab the installer from ollama.com and drag it into Applications. On Linux, the one-liner install script works fine — just inspect what it does first if you're security-conscious. On Windows, the native installer has caught up and no longer requires WSL2 for most setups.

Once installed, open a terminal and confirm it's running:

ollama --version

If that prints a version number, you're set. Ollama runs as a background service and exposes an API on localhost:11434. You don't need to start it manually; pulling a model will spin everything up.

Pulling DeepSeek V3

The model registry uses simple tags. To pull the 32B distilled version with default Q4 quantization, run:

ollama pull deepseek-r1:32b

For the smaller, faster 14B:

ollama pull deepseek-r1:14b

For the lightweight 7B that runs anywhere:

ollama pull deepseek-r1:7b

The download will take 15 to 40 minutes depending on the size and your connection. Models live in your home directory under ~/.ollama/models. If you want to move them to an external drive (the 32B is around 20 GB), Ollama respects the OLLAMA_MODELS environment variable.

Your First Conversation

Run the model interactively:

ollama run deepseek-r1:32b

The first message will take a few seconds while the model loads into memory. After that, you should get fluent, fast responses. If it feels slow, your model is probably falling back to CPU because there isn't enough GPU memory. Check Activity Monitor on Mac or nvidia-smi on Linux to confirm.

The thing that catches people off-guard with DeepSeek is the reasoning trace. The R1 variants think out loud inside <think> tags before giving you their final answer. This is intentional and it's where a lot of the model's quality comes from. Don't filter it out during development; you'll learn a lot about how the model is approaching your prompts.

Wiring It Into Your Workflow

Running the model in a terminal is fine for testing, but the real value shows up when you connect it to the tools you already use.

Set the provider to "ollama", the model to "deepseek-r1:32b", and the API base to http://localhost:11434. You'll now have inline completions and a chat panel powered entirely by your local model. No data leaves your machine, and there's no per-token cost.

For code completion specifically, the 7B variant is often a better choice than 32B — completion needs to be fast, and the smaller model returns suggestions before you finish thinking about them.

Using It as a Drop-In OpenAI Replacement

Ollama exposes an OpenAI-compatible endpoint at /v1/chat/completions. Any tool that lets you set a custom OpenAI base URL will work — just point it at http://localhost:11434/v1 and use any string for the API key. This means tools like Cursor, Aider, Open WebUI, and most agent frameworks will work without modification.

This is the single most useful thing about Ollama. You can take a Python script written against the OpenAI SDK, change one line, and have it running against your local model with zero other changes.

Performance Tuning That Actually Matters

Out of the box, Ollama makes reasonable defaults. But there are three settings worth understanding.

Context Window

The default context for most models in Ollama is 2,048 tokens, which is tiny compared to what DeepSeek V3 can actually handle. If you're working with longer documents or codebases, bump this up by creating a custom model file. The 32B handles 32K context comfortably on 64 GB of unified memory; pushing past that starts to crowd out the model weights and slows everything down.

Quantization Choice

Q4_K_M is the default and the right choice 90% of the time. If you have memory to spare and want better quality, Q5_K_M gives a noticeable bump in coherence on longer tasks. Q8_0 is essentially full precision but doubles your memory requirement. Q3 and below are not worth it for serious work — the quality drop is severe and you save almost no memory compared to Q4.

Number of GPU Layers

On NVIDIA hardware, Ollama tries to fit as many model layers on the GPU as possible. If you're seeing slow generation, it's almost always because some layers spilled to CPU. The fix is either a smaller model, a more aggressive quantization, or accepting that you need more VRAM. Apple Silicon doesn't have this problem because the GPU and CPU share memory.

The Honest Tradeoffs

Local DeepSeek V3 will not beat GPT-5 or Claude on the hardest tasks. What it will do is handle 80% of your day-to-day AI work — code completion, refactoring, drafting, summarization, debugging — at zero marginal cost, with no rate limits, and without sending anything to a third party. For a freelancer, small business, or anyone working with sensitive code or customer data, that's a meaningful change in how you can use AI.

The other underrated benefit is responsiveness. A locally-hosted 14B running on Apple Silicon will often feel faster than a frontier model over the API, because there's no network round-trip and no queuing during peak hours.

What to Try Next

Once you have DeepSeek running, the obvious next move is to give it tools. Look at Open WebUI for a polished chat interface with conversation history, document upload, and web search. For agents, frameworks like CrewAI and AutoGen work out of the box against Ollama's OpenAI-compatible endpoint. If you want to build something custom, the Python ollama package is three lines to get started.

The local AI stack has gotten dramatically more capable in the last six months. A setup that would have required a $20,000 server two years ago now runs on a mid-tier laptop, and the models are catching up to the closed ones faster than most people expected. If you've been waiting for the right moment to take local AI seriously, this is it.
