How to Run a Private AI Code Assistant in VS Code with Local Ollama in 2026

May 26, 2026 · 8 min read

Copilot is fast, but it ships every keystroke off your machine. For solo devs writing proprietary code, agencies under NDA, and teams in regulated industries, that is a problem that never quite goes away. The good news is that the local model story finally caught up. With a half-decent laptop, a free copy of VS Code, and Ollama running in the background, you can get inline autocomplete and chat that never leaves the desk. It is not as smart as the frontier hosted models, but for ninety percent of the boring work, the gap stopped mattering this year.

This is the setup I run every day on a 32 GB MacBook and the exact same one I install for clients who refuse to pipe code through someone else's API. It takes about twenty minutes from a clean machine. By the end you will have completions, chat, and codebase-aware questions answered by a model that lives on your SSD.

Why local makes sense in 2026

Three things changed. First, the open code models got serious. DeepSeek Coder V3, Qwen 2.5 Coder, and CodeStral 22B are all close enough to mid-tier hosted models that you stop noticing during normal work. Second, quantization tooling matured. You can run a 14B parameter model in roughly 9 GB of memory and still get usable speed on consumer hardware. Third, the VS Code extensions caught up. Continue and Cline both speak to Ollama natively, so wiring it all together is now a configuration file rather than a weekend project.

The privacy story is the obvious win, but there is a quieter one: cost. A heavy Copilot user pays around $19 a month, more if they use the agent features. A team of five engineers is over a thousand a year. The local stack costs you electricity and the disk space for a few model files.

What you will need

  • A machine with at least 16 GB of RAM. 32 GB is much better. Apple Silicon, recent Intel, or AMD with an NVIDIA or AMD GPU all work. A discrete GPU with 8 GB or more of VRAM will make completions feel instant.
  • About 30 GB of free disk space if you want to keep a couple of models around for different jobs.
  • VS Code installed. Cursor and JetBrains both have similar paths, but I will focus on VS Code here because it is free and the extensions are the most polished.

Step 1: Install Ollama

Go to ollama.com and download the installer for your operating system. On macOS it is a normal .app. On Linux it is a one-line install script. On Windows it is a regular installer. Once it is running you will see the little llama icon in your menu bar or system tray.

Open a terminal and confirm it works by running ollama --version. You should see a version string. Ollama runs a local HTTP API on port 11434, which is what the VS Code extension will talk to.

Step 2: Pull the right models

You actually need two models for a complete setup: a small fast one for inline autocomplete, and a larger smarter one for chat. Asking a 14B model to autocomplete every keystroke will frustrate you within an hour. Asking a 1.5B model to explain a complex bug will frustrate you within a minute. Use both.

The autocomplete model

You want something small, fast, and trained on code. The current sweet spot is Qwen 2.5 Coder 1.5B or DeepSeek Coder V2 Lite. Pull it with:

ollama pull qwen2.5-coder:1.5b-base

Use the base variant rather than the instruct variant for fill-in-the-middle completion. Instruct models are tuned for chat and will sometimes add commentary mid-line, which is awful behavior in an autocomplete context.

The chat model

This is the one that explains errors, refactors functions, and answers questions about your codebase. Go as big as your hardware will tolerate. On 16 GB of RAM, pull qwen2.5-coder:7b-instruct. On 32 GB or with a decent GPU, jump to qwen2.5-coder:14b-instruct or deepseek-coder-v3:16b. On a 64 GB workstation, codestral:22b gives noticeably better reasoning on tricky problems.

The pull will take a while the first time because these are multi-gigabyte downloads. Grab coffee.

Step 3: Install Continue in VS Code

Continue is the most mature local-first coding extension. Open the Extensions sidebar in VS Code, search for Continue, and install. You will get a sidebar icon that looks like an arrow.

Click it once to open the panel. The first time it runs, Continue will ask whether you want to use a hosted provider or run locally. Pick local. It will offer to set up Ollama for you automatically. If it asks to download a default model, you can let it, or skip and use the models you already pulled.

Step 4: Wire up the configuration

Continue stores its config at ~/.continue/config.yaml on Mac and Linux, or the equivalent on Windows. Open that file. The defaults are usable but worth a few tweaks. You want one section for chat models and one for autocomplete.

Set the autocomplete model to your small base model, and the default chat model to your larger instruct model. Also tell Continue which embedding model to use for the codebase index so it can answer questions like "where is the auth middleware defined". A small embedding model like nomic-embed-text works fine. Pull it the same way: ollama pull nomic-embed-text.

Restart VS Code after editing the config. The next time you start typing, you should see grey-text completions. Hit Tab to accept, Escape to dismiss.

Step 5: Index your codebase

Continue can index a repository so that chat questions actually have context. The first index takes a few minutes on a medium project and longer on a monorepo. Watch the status bar for progress. Once it is done, you can ask things like "summarize the routes in this app" or "where do we hash passwords" and get answers based on your actual code rather than the model's training data.

The index lives locally and updates incrementally as you edit. If you switch branches a lot, you may want to exclude generated directories and lock files via Continue's ignore settings. A bloated index slows everything down.

Tuning for daily use

Make autocomplete fast

Latency under 200 milliseconds feels invisible. Over 500 milliseconds and you start to fight it. If your completions feel sluggish, the usual culprits are the model being too big for your hardware, the context window being too long, or another heavy app eating GPU. Drop to a 1.5B model, lower the context to something like 2048 tokens, and close Chrome tabs.

Pick prompts that work

Local chat models reward specificity. Generic prompts like "improve this code" get generic answers. Prompts like "rewrite this function to use async/await, keep the error handling, and add a docstring with parameter types" get actual usable diffs. The skill of writing for a 14B model is just being slightly more explicit than you would be with GPT-5.

Keep two models loaded at once

Ollama will unload models when memory pressure rises. If you bounce between completion and chat, you will hit reload pauses. The fix is to give Ollama more keep-alive time by setting the OLLAMA_KEEP_ALIVE environment variable to something like 30m. Both models stay warm, completions stay snappy, chat stays responsive.

What you give up vs Copilot

I want to be honest about this. Frontier hosted models still beat local ones on multi-file reasoning, novel algorithm work, and obscure language quirks. If you build esoteric Rust async runtimes or you live in a 200-file Next.js app and want one prompt to update everything, hosted is still better. Where local wins is the long tail of normal work: boilerplate, refactors, docstrings, test scaffolding, explaining unfamiliar code, debugging stack traces. That is the bulk of what most of us do every day.

The other thing you give up is the polished single-vendor experience. You are responsible for picking models, updating them, and triaging weirdness. In exchange you get a setup that costs nothing per month, works on a plane, and never sends your client's code to a third party.

Going further

Once the basics are working, two upgrades pay off quickly. First, try the agent mode in Continue or look at Cline, which can run terminal commands and edit multiple files with your approval. Second, fine-tune a small model on your team's codebase. Even a few hundred examples of your house style can dramatically improve completions for your specific patterns. That is a longer post for another day.

The local AI dev stack is no longer a curiosity. It is a daily driver. Give it a Saturday afternoon. The version of you that hits paste on a long config block and watches the model spit out the next thirty lines, all without a network call, is a happier engineer.
