How to Build a Local AI Email Triage Agent with Ollama in 2026

May 24, 2026 · 7 min read

Inboxes do not get smaller. Sales pitches, newsletters, automated alerts, and the three actual emails you needed to see all pile up in the same place. The usual fix is a paid tool that ships your mail to a third-party server for processing. There is a better option in 2026: run the triage agent yourself, on your own hardware, with a small local model. Your messages never leave your machine, the only ongoing cost is electricity, and the rules are yours to write.

A local triage agent is a small script that pulls new messages, asks a local LLM to classify each one, and acts on the answer. It can add labels, move messages to folders, draft replies, or simply queue a short morning digest. Setup takes an afternoon. What follows is a complete walkthrough you can adapt to Gmail, Outlook, Fastmail, or any IMAP inbox.

What You Need Before You Start

The agent has three moving pieces: an inbox you can read programmatically, a local LLM runtime, and a small script that glues them together. Most of the work is one-time setup.

For hardware, anything with at least 16 GB of RAM and a modern CPU will run a 7B-parameter model comfortably. If you have an Nvidia GPU with 8 GB of VRAM or an Apple Silicon Mac, you will get faster classifications and can use a larger model. A Mac mini with the M4 chip handles a couple hundred emails an hour without breaking a sweat.

The shopping list is short:

  • A computer that can stay on, or wake on schedule
  • Ollama installed and running
  • Python 3.11 or newer with the imapclient and requests libraries
  • An app-specific password for your email provider (Gmail and Outlook both block plain logins)

Choosing the Right Model

Email classification does not need a frontier model. The job is to read a subject line and the first few hundred characters of the body, then output a single category. Small models do this well and run fast.

Top picks for triage in 2026

Llama 3.2 3B is the lightest option that still produces clean, structured output. It is the right pick if you are running on a laptop or a low-power home server. Pull it with ollama pull llama3.2:3b.

Qwen 2.5 7B has become the sweet spot for people doing structured tasks at home. It follows JSON output prompts reliably and handles non-English mail well. Grab it with ollama pull qwen2.5:7b.

Mistral Small 3 is a step up if you have the VRAM for it. It catches subtle distinctions, like a genuine partnership pitch versus a templated cold email, better than the smaller models. Worth it if your inbox has a lot of grey-zone messages.

For the rest of this guide we will assume Qwen 2.5 7B. Swap freely.

Setting Up Ollama

Install Ollama from the official site. On macOS it is a regular app you drag into Applications; on Linux it is a one-line installer. Once it is running, you can pull and test a model from a terminal.

Verify the install with a quick prompt:

ollama run qwen2.5:7b "Classify this email as urgent or not: Quick question about the contract, can you take a look today?"

If you get a coherent answer in a few seconds, you are set. Ollama exposes a local HTTP API on port 11434, which is what your triage script will talk to.

Keep the model warm

Cold-start latency is the main thing that makes a local agent feel sluggish. Ollama unloads models after a few minutes of inactivity by default. Set OLLAMA_KEEP_ALIVE=-1 in your environment to keep the model resident, or pass keep_alive: -1 in the API request. Memory is cheap; the latency tax is annoying.

Connecting Your Inbox

Email APIs vary, but IMAP works everywhere. For Gmail, generate an app password in your Google Account security settings, which requires two-factor auth first. For Outlook, generate one in Microsoft account security. Other providers usually have a similar option buried in the same place.

Once you have a password, a few lines of Python connect and pull unread messages. The library imapclient is the cleanest option in 2026. It returns plain dictionaries and handles the obscure parts of the IMAP protocol so you do not have to. Install it with pip install imapclient.

A minimal fetch loop opens a connection, selects the inbox, searches for unread messages from the last hour, downloads them, and yields each one to your script. That is the entire input side, and it is maybe twenty lines of code.

For Gmail specifically, you can use the X-GM-LABELS extension to read and write Gmail labels directly through IMAP, which is what you want for the act-on step later.

Writing the Triage Prompt

This is the part you will iterate on. A good triage prompt has three pieces: a clear set of categories, a few examples, and a strict output format.

A starter prompt

You are an email triage assistant. Read the email below and classify it into exactly one category:

  • URGENT — needs a response today
  • WAITING — someone is waiting on me, but not today
  • NEWSLETTER — bulk content I might read later
  • RECEIPT — order confirmation, invoice, or shipping update
  • NOISE — promotional, automated, or low-value
  • PERSONAL — from a friend or family member

Output only a JSON object with three keys: category, confidence (0 to 1), and reason (one short sentence). Then pass in the subject, sender, and the first 800 characters of the body.

Three things make this prompt work. First, the categories are mutually exclusive, so the model is not being asked to pick a vibe. Second, the JSON output is easy to parse and easy to validate. Third, the body is truncated so the model is not fed entire newsletters.

Add your own examples

The single biggest improvement comes from adding three or four examples of edge cases that exist in your inbox. Vendor pitches that look like personal outreach, automated alerts from systems you actually care about, recurring newsletters from people you genuinely want to read — drop two-line examples of each into the prompt and watch accuracy jump.

Putting It All Together

The full script is small. It runs a tight loop:

  • Connect to IMAP
  • Fetch unread messages since the last run
  • For each message, send subject and body to Ollama
  • Parse the JSON response
  • Apply a label or move the message based on the category
  • Mark the message as read, or leave it unread per your preference

Save the timestamp of the last run so you do not re-process the same mail. A tiny SQLite database or a single text file works fine. About 120 lines of Python in total once you handle errors.

A few details worth getting right: catch JSON parse errors from the model and re-prompt once before giving up; log every classification to a CSV so you can review accuracy later; never delete mail from the script — labels and folders only. The first rule of building automation around your inbox is that the automation should be reversible.

Scheduling and Running It

On macOS, a launchd agent or a cron entry every fifteen minutes works well. On Linux, systemd timers. On Windows, Task Scheduler. The script should be safe to run while it is already running — a simple lock file in /tmp is enough.

For a snappier experience, run it as a long-lived process that polls IMAP IDLE, the protocol's built-in push notification, and processes mail the second it arrives. Both imapclient and aioimaplib support IDLE. With a warm model you will see new mail labeled within two or three seconds of hitting your inbox.

Tuning the System Over Time

The agent gets better the more you watch it. For the first week, label every classification in your CSV log as correct or wrong. Look at the wrong ones. They almost always cluster — same kind of sender, same kind of subject pattern. Add a one-line example to your prompt that fixes the cluster, and the next week's accuracy jumps.

After a month, you will have an agent that knows your inbox better than any cloud service ever could, because you tuned it on the actual mail you actually get. And it runs forever for the cost of leaving a small computer on.

When to upgrade your model

If the 7B model starts struggling on a category that matters — say, distinguishing investor outreach from generic networking spam — try a 13B or 14B model before changing the prompt. The jump in reading comprehension is bigger than the jump in size suggests. Mistral Small 3 and Qwen 2.5 14B both fit on a 24 GB GPU and run at usable speed on Apple Silicon, too.

Adding draft replies

Once classification is solid, the next layer is auto-drafting. Pick one category, say URGENT, and add a second Ollama call that takes the email and a short writing sample of yours, then proposes a two-paragraph response saved to your Drafts folder. You still hit send by hand; the agent saves the cold-start writing minute. People who add this step often find it is the single biggest time win of the whole project.

Where to Take It Next

The triage agent is a foundation. The same pattern works for meeting requests (route them to a calendar agent), invoices (pipe them into your bookkeeping tool), and even suspicious mail (a local agent has time to actually read a phishing attempt and tell you what is sketchy about it). Once one local agent is running, the second is a copy and a new prompt.

The point is not to remove email. It is to remove the part of email where you are acting as a low-paid sorter for senders who did not earn your attention. A 7B model running on a box in your closet is now perfectly good at that job. Hand it off and get back to the three emails that actually matter.
